# SSE와 WebSocket

## Server-Sent Events (SSE)

별도 설정 없이 일반 HTTP 요청으로 보낸다. 응답의 `Content-Type`이 `text/event-stream`이면 자동으로 스트리밍 모드가 된다.

- 응답의 Body 탭이 **Events**로 바뀌고, 이벤트가 도착하는 대로 목록에 한 줄씩 추가된다 (시각, 이벤트 이름, id, data). 줄을 누르면 data가 JSON이면 펼쳐서 보여준다.
- Auto-scroll로 새 이벤트를 따라 내려갈지 정한다.
- 응답 헤더를 받기 전에는 URL 바의 Cancel로, 스트림이 열린 뒤에는 Events 화면의 **Stop**으로 끊는다. 서버가 끊으면 종료로 표시된다.
- 이벤트는 최대 5000개까지 보관한다.
- Post-response 스크립트는 실행하지 않는다 (완결된 본문이 없기 때문).

## WebSocket

컬렉션·폴더 우클릭 → New WebSocket으로 만든다. 요청처럼 YAML 파일 하나로 저장된다.

### 연결

- URL(`ws://`, `wss://`)에 변수를 쓸 수 있다.
- Headers 탭에서 연결 요청 헤더를, Settings 탭에서 서브프로토콜을 지정한다.
- Connect / Disconnect로 연결을 열고 닫는다. 연결 상태가 표시된다.
- `wss://`는 전역 설정의 Verify SSL을 따른다.
- 프록시 설정은 적용되지 않는다.

### 메시지

- **Message** 탭의 편집기에 내용을 쓰고 보낸다. 텍스트(JSON 문법 강조) 또는 바이너리(base64 입력)를 고른다. 텍스트를 base64로 바꿔 주는 버튼이 있다. 변수를 쓸 수 있다.
- 자주 보내는 메시지는 이름을 붙여 저장해 두고, 목록에서 골라 다시 불러오거나 지운다. 저장 메시지는 WebSocket 파일을 저장(⌘S)할 때 YAML에 함께 기록된다.

### 로그

- 보낸 메시지, 받은 메시지, 연결·종료·오류 이벤트가 시간순으로 쌓인다. 다시 연결해도 로그는 이어지며, 최대 5000개까지 보관한다.
- 메시지마다 방향, 시각, 크기가 표시되고, 바이너리는 16진수 미리보기로 보인다.
- Filter로 메시지 내용을 걸러 보고, 로그를 지울 수 있다.
